# GitHub APK Updater Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Android players discover, download and install verified GitHub updates from Home while retaining their saved game.

**Architecture:** Android owns release selection, HTTPS transfers, private candidate storage and PackageInstaller sessions. A three-command bridge reports Home visibility, requests metadata checks and opens a native dialog; only native dialog buttons download or install. Small policy and controller modules are independently testable, with Android adapters behind constructor-injected interfaces.

**Tech Stack:** Existing Java 17 / Android SDK 36 / minSdk 26, platform HTTPS and PackageInstaller, JavaScript ES2017, Node test runner and Playwright. Use plain Java assertions and a custom platform Instrumentation runner; no new shipped dependency or AndroidX requirement.

**Spec:** `docs/superpowers/specs/2026-10-15-github-apk-updater-design.md` — approved by the user on 2026-10-15. Read it before this plan.

## Global Constraints

- First version **0.11.0**, Android version code **15**, multiplayer protocol **8** unchanged; package `au.local.blockops`, minSdk **26**, targetSdk **36**.
- Preserve the signing certificate SHA-256 `6b2d84eb4133168fec0850ed710acffa01d8399b75c8410621b2d0ce9881cb49`; never regenerate a missing signing key or uninstall to make an upgrade work.
- Fixed production endpoint `https://api.github.com/repos/uptecio/byd-blockops/releases/latest`; no token, endpoint override, downloaded script or remote WebView page.
- Stable tags `vMAJOR.MINOR.PATCH`; exactly one `block-ops-*.apk`; valid API `sha256:` digest or one exact `SHA256SUMS` entry. A malformed present digest fails closed.
- Successful-check cache **six hours**; automatic-failure backoff **fifteen minutes**; manual minimum interval **thirty seconds**; both respect a longer server retry deadline.
- Metadata/checksum maximum **512 KiB** each; APK maximum **100 MiB**; connect timeout **ten seconds**, read timeout **thirty seconds**, total transfer deadline **five minutes**, maximum **five redirects**.
- HTTPS hosts only: `api.github.com`, `github.com`, `release-assets.githubusercontent.com`, `objects.githubusercontent.com`; no user information or nonstandard port. Initial assets must belong to this repository and selected release.
- Add only `android.permission.REQUEST_INSTALL_PACKAGES` to INTERNET. No storage/notification permission, service, forced update or silent installer.
- Foreground-only transfers; cancel incomplete downloads on actual backgrounding or leaving Home, but preserve them across foreground Activity recreation. Complete candidates require revalidation before installation.
- Preserve packaged origin `https://appassets.androidplatform.net/assets/index.html`, WebView profile, save keys, CSP, navigation restrictions and disabled file/content access.
- Browser builds have no APK updater UI or GitHub requests. No changes to live servers, rooms, old releases or private photos. All GitHub operations use authenticated `gh`.
- Execution starts only after plan review and method selection. Use the worktree skill at execution time; do not infer a checkout choice from old feature approvals. Capture clean baseline, owned build paths and hashes before implementation.

## Review Focus

1. Device wall-clock jumps or corrupt persisted deadlines must not suppress checks indefinitely or cause request storms — Task 4.
2. Late callbacks after cancellation, Home exit or Activity recreation must not revive stale UI or start an installer — Tasks 2, 4 and 5.
3. Encoded filenames, deceptive hostnames, foreign repositories and duplicate assets must never select an untrusted APK — Tasks 1 and 2.
4. A release whose asset changes between discovery and download must require a fresh decision, not install a stale selection — Task 4.
5. Process death around installer commit must not submit a second session or destroy the existing save — Tasks 3 and 6.

## File map and shared contracts

Place native updater classes in `android/app/src/main/java/au/local/blockops/updates/`. MainActivity remains an integration point. Native classes below use that package; test-only classes may use the same package to access narrow package-private seams.

| Files | Responsibility |
| --- | --- |
| `UpdateModel.java`, `UpdatePolicy.java`, `UpdatePorts.java`, `UpdateCancellation.java` | Immutable data, pure validation, explicit side-effect interfaces and cancellation |
| `GithubReleaseClient.java`, `HttpsUpdateTransport.java` | Bounded HTTPS and GitHub JSON decoding |
| `UpdateCandidateStore.java`, `AndroidApkVerifier.java` | Private files, checksums, package and signer inspection |
| `AndroidUpdateInstaller.java`, `UpdateInstallReceiver.java` | Permission flow, owned sessions and status callbacks |
| `UpdateController.java`, `UpdatePreferences.java` | State transitions, check scheduling, persistence and asynchronous generations |
| `UpdateDialog.java`, `UpdateBridge.java` | Native controls and the three-command WebView boundary |
| `android/app/src/main/java/au/local/blockops/BlockOpsApplication.java` | Application-scoped production service factory and foreground tracking |
| `src/update-ui.js` | Optional Android Home notice and manual check control |
| `android/tests/updater-*.mjs`, `android/tests/Updater*Test.java` | Host verification and dependency-free JVM tests |
| `android/app/src/androidTest/` | Instrumentation-only fixtures; never shipped in the game APK |

`UpdateModel` provides immutable Java classes, not records: `Version(major,minor,patch)`, `Asset(id,name,uri,size,digest)`, `Release(id,tag,version,asset,sha256,summary)`, `InstalledApp(packageName,versionName,versionCode,signerSha256,sdkInt)`, `ApkIdentity(packageName,versionName,versionCode,signerSha256,minSdk)`, `Candidate(file,release)`, `Snapshot`, `SavedState`, and `InstallEvent(sessionId,phase,message)`. IDs/version codes/byte counts are longs; versions are three bounded nonnegative ints. One signer is supported. Candidate paths never enter Snapshot.

`Snapshot` contains only `revision`, `phase`, `installedVersion`, nullable `availableVersion`, `totalBytes`, `downloadedBytes`, `message`, and `dismissed`. Phases are `idle`, `checking`, `current`, `available`, `downloading`, `verifying`, `ready`, `permission`, `installing`, and `error`. Increment revision for observable changes; strings are bounded and plain text. SavedState contains `lastSuccessWallMillis`, `lastFailureWallMillis`, `serverRetryUntilWallMillis` and nullable `cachedRelease`. CandidateStore owns complete candidate identity; SessionStore owns the recorded installer session ID. None stores game saves or the session-only Later choice.

`UpdatePorts` defines `Clock.wallMillis()/elapsedMillis()`, `ReleaseSource.latest(UpdateCancellation): Release`, `Downloader.download(Release,UpdateCancellation,Progress): Candidate`, `Progress.onBytes(long,long)`, `Verifier.inspect(Candidate,InstalledApp): ApkIdentity`, `StateStore.load()/save(SavedState)`, `SessionStore.get(): Integer/set(Integer): void`, and `Installer`. `CandidateStore extends Downloader` adds `load(): Candidate` (nullable), `deletePartial(): void` and `forget(): void`; these affect only owned updater files. Verifier performs full byte/digest and native identity validation, not just metadata parsing. Installer methods are `allowed(): boolean`, `openPermissionSettings(): void`, `commit(Candidate): int`, `confirm(int): void`, `reconcile(Integer): InstallEvent`, `cancelOwned(int): void`, and `setListener(Consumer<InstallEvent>): void`. A `Listener.onState(Snapshot)` receives controller state. Checked failures carry a fixed error code, safe message and optional server retry deadline, never response bodies or signed URLs.
