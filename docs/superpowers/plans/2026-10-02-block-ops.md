# Block Ops Implementation Plan

> **For agentic workers:** Execute the independent modules in parallel with explicit ownership; the primary agent integrates and verifies the complete game. Steps use checkbox tracking.

**Goal:** Deliver a playable offline touchscreen shooter and Android APK with 28 guns across seven switchable classes.

**Architecture:** Bundled Three.js scene plus HTML interface, independent weapon and match modules, and a minimal Android asset-hosting Activity. Pure collision helpers are shared by player movement, bots and line-of-sight checks.

**Tech Stack:** JavaScript ES2017 bundle, Three.js 0.160.1, esbuild, Node test runner, Playwright, Android Java 17 / SDK 36.

**Spec:** ../specs/2026-10-02-block-ops-design.md

## Global Constraints

- Offline at runtime, no internet permission or remote assets.
- Seven classes, 28 guns, all unlocked, fictional game statistics.
- Landscape; Android minSdk 26, compile/target SDK 36.
- Round: 180 seconds or 15 eliminations; default five bots, adjustable one to eight.
- Preserve ammo on in-match weapon switching; pause on menus/background; clear touch input on cancellation.

## Review Focus

- Multiple simultaneous pointers must move/aim/fire independently and release reliably.
- Backgrounding and menu transitions must not advance combat or leave fire held.
- Switching guns must not duplicate reserve ammo or leave stale reload state.
- Bots and hitscan must respect arena walls; player cannot exit bounds.
- Offline packaged assets and landscape UI must work at short screen heights.

## Implementation record

The approved mockup plus the user's instruction to make the gun classes switchable provided implementation scope. Work stayed in the originally empty workspace on a new local branch; no external deployment or vehicle installation was performed. Parallel tasks had disjoint ownership.

Validation: 32 Node tests pass, including integrated hitscan/cover, lethal bot damage and round victory. Browser and real CDP multi-touch suites pass. A quick press could originally be lost between frames; the failing browser test drove a queued press fix. Independent review found backward/arrow-key movement omitted from bot accuracy adjustment; a regression test failed on KeyS, then passed for all eight movement keys after the fix. APK signature and bundled JavaScript checksum verified against the final dist build.

The final APK was installed on a disposable Android emulator with networking disabled. Menu, deployment, landscape rendering, native Back pausing, Home/background pausing and foreground staying paused all passed. Raw Chrome DevTools Protocol checks avoided a browser-test framework's artificial document visibility override. The emulator is separate from the user's vehicle; this is not BYD hardware validation.

Scope limits: one procedural map, offline bot matches, stylised models with fictional weapon balance, a debug-signed testing APK, no physical BYD validation or vehicle-motion integration. Android installation permissions and rendering performance depend on the actual head unit.
